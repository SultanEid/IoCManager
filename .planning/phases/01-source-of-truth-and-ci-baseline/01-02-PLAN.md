# Plan 01-02: Noisy-path boundary and guardrails

<objective>
Make the active-source boundary enforceable without deleting user material. This plan covers GOV-02 and decisions D-01, D-02, D-03, D-04, D-09, D-10, and D-11.
</objective>

<context>
- Phase context: `.planning/phases/01-source-of-truth-and-ci-baseline/01-CONTEXT.md`
- Research: `.planning/phases/01-source-of-truth-and-ci-baseline/01-RESEARCH.md`
- Current ignore policy: `.gitignore`
- Existing scope guard: `Workspace/Project/scripts/check-ioc-scope.ps1`
- Codebase concerns: `.planning/codebase/CONCERNS.md`
</context>

<must_haves>
<truths>
- D-01: `Workspace/Project/` is the only active application root for new product work.
- D-02: `src/IocManager.Web` is removed/decommissioned and should not be reintroduced.
- D-03: Phase 1 should enforce the canonical-root boundary, not merely mention it.
- D-04: Enforcement must preserve existing user material unless a later explicit cleanup task requests deletion.
- D-09: Update ignore policy and document cleanup boundaries for logs, screenshots, scanner result folders, temp copies, backups, and generated output.
- D-10: Distinguish "ignore going forward" from "delete existing material"; deletion is out of scope.
- D-11: Make code search, dependency review, and security scanning focus on active source by default.
</truths>
<acceptance>
- A repository-boundary document explains active, reference, generated, local-only, and removed path categories.
- `.gitignore` contains clear rules for newly generated noise without untracking existing user files.
- A PowerShell guard script fails if removed roots or noisy/generated files are tracked in ways that violate the boundary.
- The guard script does not delete files.
</acceptance>
</must_haves>

<threat_model>
<threat id="T-02-01" severity="medium">
Noisy tracked files or removed roots can hide source-of-truth drift, inflate reviews, and cause agents to scan or modify irrelevant material.
</threat>
<mitigation>
Document the boundary, keep ignore policy explicit, and add a guard script that detects violations without destructive cleanup.
</mitigation>
<verification>
Run the guard script and inspect output. It must pass on allowed current material or report actionable, non-destructive findings.
</verification>
</threat_model>

<task id="1-02-03" type="auto">
<title>Add repository-boundary guard script</title>
<files>
- `Workspace/Project/scripts/check-repository-boundaries.ps1`
</files>
<action>
Create a PowerShell script that:
1. Runs from repo root by default.
2. Uses `git ls-files` to inspect tracked files only.
3. Fails if tracked files appear under removed roots such as `src/IocManager.Web/`.
4. Warns or fails for tracked noisy/generated paths according to the documented boundary: logs, screenshots, result folders, temp folders, backups, local Playwright/VS state.
5. Allows explicit active paths under `Workspace/Project/`, `.planning/`, `AGENTS.md`, `README.md`, `.gitignore`, and `.github/`.
6. Prints actionable messages and never deletes files.
</action>
<verify>
Run `powershell -NoProfile -ExecutionPolicy Bypass -File Workspace/Project/scripts/check-repository-boundaries.ps1`.
</verify>
<acceptance_criteria>
The script exits non-zero only on real boundary violations and gives precise path-level output.
</acceptance_criteria>
</task>
